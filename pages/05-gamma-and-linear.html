05 — Gamma & linear light

In sRGB images, the numbers you see (0–255) are not proportional to light. That’s why “mixing colors by averaging RGB” can look wrong.

Big idea: To blend lights correctly on a screen, you should mix in linear light, not directly in sRGB numbers.

Half the number isn’t half the light

If you set a channel to 128, it’s not “half as bright” as 255. Your eyes are more sensitive to changes in dark areas, so images store numbers in a curved way.

Why gamma exists

sRGB uses a curve so we spend more code values on dark tones where humans notice differences more. But physics (light adding) is linear. So for correct blending: sRGB → linear → mix → sRGB.

sRGB transfer function (EOTF/OETF)

sRGB is approximately power-law (with a linear segment near black). For channel value c in [0,1]: convert to linear, perform operations, then convert back for display encoding.

This matters for compositing, filtering, mipmaps, and physically meaningful rendering pipelines.

What you learned

Short recap.

  • sRGB values are encoded for storage/perception, not linear light.
  • Correct light blending: sRGB → linear → mix → sRGB.
  • This is why many “naive” blends look too dark or off.
