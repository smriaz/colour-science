About Color Lab

This is a pure-vanilla, web-based interactive tutorial for color science — designed to work for school learners through university students, with a special emphasis on vision science and printing.

🧪 learn-by-doing 🧠 vision + perception 🖨️ printing workflows 🧰 vanilla HTML/CSS/JS
Guiding rule: each page explains the idea first, then adds interactivity. The goal is understanding, not memorizing formulas.
Important: Some demos use toy models to build intuition. They’re deliberately simplified (fast + visual) and not a replacement for calibrated, profile-based, or spectral workflows.

How to use this tutorial

Start at Home, follow the “Next” buttons, and use the level toggle whenever things feel too easy or too spicy.

1) Choose a level

Use the top toggle: Kids/Beginner, Intermediate, University. It changes the explanation depth.

2) Read first, then play

Each page explains the concept, then gives a demo or challenge.

3) Use the glossary as a “pause menu”

If a term appears and you don’t know it, jump to Glossary, then come back.

Who is this for?
  • School learners: get the intuition and vocabulary.
  • Undergrads: connect perception to color spaces and conversions.
  • Printing / imaging folks: build a mental model for profiles, gamut, and QA.

What “toy model” means (honestly)

Toy models are simplified approximations that are good for learning. They’re fast to compute and visually clear.

  • Good for: intuition, cause-and-effect, “what changes when I move this slider?”
  • Not good for: accurate prediction for a specific printer/paper/spectrum without profiles
Examples in this project
  • CMYK preview: simple absorption-style model (not a profile-based conversion)
  • Gamut plots: illustrative polygons and field mapping (not a measured device gamut)
  • CVD simulation: simple matrix intuition (not clinical diagnosis)
The upgrade path: later pages can add real ICC transforms, measured spectral data, and accurate chromaticity/appearance models.

Site structure

The tutorial is a set of static pages in a GitHub repo. Navigation is simple: Home + Previous/Next + Glossary/About.

What’s inside

  • Lessons: one topic per page (with a mini demo)
  • Glossary: definitions + quick-check game
  • Resources: what to read next (vision + printing)

Repo-friendly design

  • Pure HTML/CSS/JS (no build tools)
  • Works on GitHub Pages
  • Accessible-ish defaults (skip link, semantic structure)
  • Local-only state (level setting stored in browser)
